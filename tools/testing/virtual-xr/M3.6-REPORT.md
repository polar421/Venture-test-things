This is a sanitized report. It omits local paths, process IDs, host profiling,

made: the missing type is not present in the Roblox APK, while the converter
preserves every class the APK does define. No fake `ExceptionManager`, listener,

## APK findings

Tested Roblox package version `2.747.1485` (versionCode `21668`). The APK has
two root DEX containers:

| DEX | Size | Defined classes | Methods | Fields |
|---|---:|---:|---:|---:|
| `classes.dex` | 8,634,684 bytes | 11,435 | 61,777 | 36,438 |
| `classes2.dex` | 5,731,148 bytes | 6,721 | 43,933 | 17,283 |

The two DEX files define 18,156 unique classes. The following types are
referenced but have no `class_def` in either DEX:

- `com.appsflyer.exception_manager.ExceptionManager`
- `com.appsflyer.exception_manager.ExceptionManager$ConfigurationChangedListener`
- `com.appsflyer.exception_manager.ExceptionManagerImpl`
- `com.appsflyer.exception_manager.SdkData`
- `com.appsflyer.exception_manager.ExceptionManagerInitProvider`

`classes.dex` contains the listener type at type-table index 2591 and exactly one
method reference to it:

```text
com/appsflyer/internal/AFa1tSDK.init:
  ExceptionManager.init(ExceptionManager$ConfigurationChangedListener)
```

The APK does define `com/appsflyer/internal/i`, which implements the missing
nested listener, and `com/appsflyer/internal/AFc1aSDK` has a field whose type is
the missing outer `ExceptionManager`. Those definitions are preserved, but their
required interface/type is not present.

The binary manifest contains AppsFlyer referrer entries but no
`com.appsflyer.exception_manager.ExceptionManagerInitProvider` provider.
The AppsFlyer base SDK in the APK is version `7.0.1`, matching the separately
published optional `com.appsflyer:exception-manager:7.0.1` artifact.

## Conversion findings

Venture's conversion pipeline reads every root `classes*.dex`, converts each DEX
independently, and merges the converted JARs. The generated JAR was compared
against the strict DEX class census:

```text

JAR classes:         18,156
DEX classes missing from JAR: 0
JAR classes not defined by DEX: 0
DEX natives: 727
JAR natives: 727
```

The converted JAR contains `com/appsflyer/internal/i.class` and
`com/appsflyer/sdk_base/exception_manager/ExceptionManagerConfiguration.class`.
It does not contain the missing listener, outer interface, implementation,
`SdkData`, or provider. The converter's missing-linkage report is therefore
correctly describing an absent optional dependency rather than dropping a
defined class.

The conversion report remains `ready: false`, but
`translation_complete: true`: intact code was translated; the absent vendor
linkage is deferred until reached. HotSpot then reports the missing class when
`AFa1tSDK` is verified.

## Official contract

The published optional artifact declares these types:

```java
public interface ExceptionManager {
  void init(ExceptionManager$ConfigurationChangedListener listener);
  void sendExceptionsToServerIfNeeded();
  void updateExceptionManagerConfiguration();
  void storeNewException(Throwable throwable, String detail);
}

public interface ExceptionManager$ConfigurationChangedListener {
  void onConfigurationChanged(boolean enabled);
}
```

The artifact also contains the implementation, `SdkData`, and a manifest
`ExceptionManagerInitProvider`. Its POM identifies the license as
`Proprietary` and depends on `com.appsflyer:af-android-sdk-base:7.0.1`.

This is not an Android framework type and it is not supplied by Venture's
framework or JRE. Reproducing the implementation would require the proprietary
AppsFlyer behavior and permissions that are not available for this milestone.
An interface-only stub would still leave the outer class, implementation,
provider, and behavior missing; a no-op implementation would fabricate vendor
semantics and suppress an error without establishing correct behavior.

## Virtual runtime result

The preserved M3.3 AppImage was checksum-verified and run through the portable
M3.5 launcher with one isolated Monado QWERTY service. WiVRn and the system
OpenXR registration were left untouched. The service and runtime were stopped
afterward.

Roblox reached:

- host OpenXR initialization;
- an OpenXR instance and system using the QWERTY HMD and controllers;
- `ActivitySplash` creation and resume;
- startup-cache, DNS, and TLS prewarming;
- `AppsFlyerManager` construction and `initEnabled=true`.

It then failed on the Android main thread at `AppsFlyerLib.getInstance`:

```text
java.lang.NoClassDefFoundError:
com/appsflyer/exception_manager/ExceptionManager$ConfigurationChangedListener
```

No RingtoneManager, WindowInsets, authentication, or playable online session
result is claimed. Reaching OpenXR setup is not a working Roblox result.

## Conclusion

This is Case C (missing optional dependency) with a Case D resolution: Roblox
7.0.1 references AppsFlyer's optional exception-manager module but does not
package it, and the official implementation is proprietary. Venture's converter
and classloader are behaving correctly. No safe source-level compatibility fix
is available under the milestone boundaries.
