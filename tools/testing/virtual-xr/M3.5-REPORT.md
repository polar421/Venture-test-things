# M3.5 — Virtual XR stability and input verification

This is a sanitized copy of the M3.5 findings. It intentionally omits local
paths, process IDs, window IDs, host profiling, and private device identifiers.

## Runtime

- Monado 25.1.0-1106
- QWERTY virtual HMD and left/right controllers
- Private `XDG_RUNTIME_DIR` and an explicit per-application `XR_RUNTIME_JSON`
- One persistent service reused across clients
- WiVRn and the system OpenXR registration left untouched

## Root cause and fix

The previous service lifecycle allowed standalone `monado-service` to poll
stdin. Stdin readiness or HUP was treated as a shutdown request, so the service
could exit after a client disconnected. That removed the IPC socket and the
one-time QWERTY/debug GUI; the next client then had no service to reach.

The durable launcher uses:

```text
XRT_NO_STDIN=1
IPC_EXIT_ON_DISCONNECT=0
IPC_EXIT_WHEN_IDLE=0
```

and starts the service with stdin from `/dev/null`. The service then survives
client exit and idle gaps, and is stopped only by the explicit stop command.

## Results (virtual only)

- Five consecutive OpenGL `hello_xr` sessions used the same service.
- Every session reached `FOCUSED`, submitted frames, and exited normally.
- The QWERTY debug GUI remained present across all five sessions.
- Head translation with `A`/`D` moved in opposite directions; `Right`/`Left`
  produced opposite orientation changes.
- Left-controller movement changed only the left controller pose; right-
  controller movement changed only the right controller pose.
- Real middle-click grip events produced `grab_object` press and release
  transitions on both controllers.
- A real menu-button event produced a `quit_session` boolean transition.
- Super RC, Untangled, and BattleGlide reached OpenXR sessions sequentially on
  the same service. Frame submission and zero `xrEndFrame` errors were recorded
  where noted in the original evidence; a frame count is not visual validation.
- Roblox still failed before XR with:

```text
java.lang.NoClassDefFoundError:
com/appsflyer/exception_manager/ExceptionManager$ConfigurationChangedListener
```

M3.5 did not implement AppsFlyer compatibility and did not claim Roblox works.

## Limitations

- Virtual Monado/QWERTY only; no physical Quest, WiVRn, microphone, camera,
  passthrough, eye/hand tracking, or attestation result.
- In-game controller behavior was not verified; the input result is the host
  OpenXR/QWERTY path.
- No game screenshots or visual-quality review were part of M3.5.
- External timeout wrappers can leave detached game/runtime processes after the
  bounded run; the harness does not kill arbitrary user-started process trees.
- Performance samples from the original run were host-specific and are not part
  of this portable record.
